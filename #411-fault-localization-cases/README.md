Group 411 - Fault Localization - Test Cases Dataset

This repository contains 5 test scenarios. Each scenario follows a fault assumption design: a sequence of successful, normal steps that ultimately leads to one intentional, critical bug (e.g. state management inconsistencies, network timeouts, or logical errors).

Included Scenarios
1. Passo App
2. Bank App
3. Ticket App
4. Rent a Car App
5. Wikipedia Website

Folder Structure
Each of the 5 scenario folders contains the following structure:

- /photos/ - The raw screenshot images (pre-action and post-action) representing the visual state of the application at each step.
- [case-name]-fail.json - The Input file (The Test Trace).
- [case-name]-output.json - The Output file (Expected Result).

Files

1. The Input File (*-fail.json)
This file simulates the test execution trace. It provides the AI agent with all necessary context to evaluate the step. Inside, you will find an array of steps containing:
- stepInstruction: The natural language command (e.g. "Click the checkout button").
- action: The interaction type (click, type, assert, waitUntil).
- prevScreenshot & currScreenshot: Visual states before and after the action.
- consoleLogs & networkLogs: Contextual background system data to help differentiate between frontend and backend failures.

2. The Output File (*-output.json)
This is the final analysis report generated by agent pipeline. You can use this to benchmark your own system's reasoning. Key fields include:
- status_summary: Overall count of PASS, FAIL, and UNKNOWN steps.
- status: The evaluation result per step.
- confidence_label & confidence: The AI's certainty metric (high, medium, low).
- reason: The step-by-step logical reasoning of the agent.
- failures: A detailed root cause analysis explaining exactly why the test failed (e.g. "UI Failure", "Backend Failure") and describing the logical/visual inconsistency.
